# Неисправности: симптом → причина → что делать

Начинай с `lobzik.py info`: он показывает версию зонда, напряжение цели и найденные ядра.

## Зонд

| Симптом | Причина | Что делать |
|---|---|---|
| `list` пуст | кабель только для зарядки, Лобзик в DFU | другой кабель; в DFU он виден как «STM32 BOOTLOADER» (0483:df11) — `reflash` |
| два порта есть, GDB не отвечает, таймаут | зонд подвис (бывает после обрыва посередине записи) | переподключить USB Лобзика |
| `Access denied` / порт занят | порт держит VS Code, другой GDB, монитор порта | закрыть программу; в Windows проверить, что не висит старый `arm-none-eabi-gdb` |
| номера COM растут при каждом подключении (Windows) | Windows запоминает каждый серийный номер | не мешает; порты скрипт находит сам |
| Linux: `Permission denied` на /dev/ttyACM* | нет прав на порт | добавить пользователя в группу `dialout` (или `uucp`), перелогиниться |
| Linux: порт «мигает», GDB рвётся | ModemManager опрашивает новые модемы | отключить ModemManager или udev-правило `ENV{ID_MM_DEVICE_IGNORE}="1"` для 1d50:6018 |

## Цель

| Симптом | Причина | Что делать |
|---|---|---|
| `Target voltage: 0.0V` | нет питания цели или не подключён VTref (контакт 3) | подать питание; `power on` |
| `Target already powered` на `power on` | у цели своё питание | так и задумано — зонд не включает второй источник |
| напряжение есть, `No usable targets` / `SW-DP scan failed` | шлейф (SWDIO/SWCLK/GND), не тот режим, высокая частота, SWD-выводы перенастроены прошивкой | проверить шлейф; `--freq 500k`; JTAG-цель — `--jtag`; `--halt-timeout`/подключение под сбросом: `gdb "mon connect_rst enable" ...` |
| ядро в списке, `Attaching to Remote target failed` | ядро не остановилось за 2 с: глубокий сон, странное состояние после сбоя | `--halt-timeout 5000`; не помогло — сбросить цель кнопкой, nRST или питанием |
| цель уходит в Stop/Standby, отладка отваливается | при сне отключается отладочный домен | в прошивке включить отладку во сне (у STM32 — биты DBGMCU_CR: DBGSLEEP/DBGSTOP/DBGSTBY) или подключаться под сбросом |
| `reset` (sys) ничего не сделал | ядро зависло так, что не выполняет SYSRESETREQ, или это не Cortex-M | `reset --reset hw` (нужен nRST на контакте 12), кнопка сброса на плате, питание |
| `reset --reset hw` ничего не сделал | nRST не подключён к контакту 12 | подключить или сбросить иначе |

## Запись

| Симптом | Причина | Что делать |
|---|---|---|
| запись идёт ~2 КБ/с | частота SWD по умолчанию | `--freq 2M` (у скрипта уже по умолчанию) — ~23 КБ/с |
| `MIS-MATCHED` при сверке | сбои на линии, flash защищён, запись поверх неочищенного | понизить `--freq`, проверить защиту (RDP/WRP), повторить |
| `Error erasing flash` / `Load failed` | защита от записи/чтения, неверный адрес BIN | снять защиту (у STM32 — Option bytes через STM32CubeProgrammer), для BIN указать `--address` |
| запись прошла, плата не стартует | неверный адрес BIN, нет сброса, прошивка падает сразу | для ELF адрес берётся из файла; `uart --reset`, затем `regs` |
| сверка не запускается: `exec file` | GDB без `file <elf>` | скрипт делает сам; в ручном GDB — сначала `file` |

## UART

| Симптом | Причина | Что делать |
|---|---|---|
| тишина | не та скорость, перепутаны 13/14, порт занят, прошивка пишет в другой UART | `--baud`; контакт 13 — к RX цели, 14 — к TX цели; закрыть терминал |
| мусор | скорость не совпадает, разный уровень (нет VTref) | `--baud`, проверить VTref |
| нет начала лога | порт открыт после старта платы | `uart --reset` |
| русский текст кракозябрами | исходник не в UTF-8 | сохранить исходники в UTF-8; скрипт декодирует вывод как UTF-8 |
