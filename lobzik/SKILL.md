# Лобзик — отладчик на Black Magic Debug

Лобзик сам является GDB-сервером: OpenOCD, ST-Link и драйверы не нужны. GDB подключается
к его COM-порту командой `target extended-remote <порт>`. Всё, что ниже, делается через
`scripts/lobzik.py` — он находит порты, запускает GDB в пакетном режиме и выходит,
поэтому порт после него свободен. Пиши свой GDB-скрипт, только если команды скрипта
не хватает (тогда — `references/gdb.md`).

## Что нужно на ПК

- Python 3.8+ и `pip install pyserial`
- GDB под архитектуру цели: `arm-none-eabi-gdb` (Arm GNU Toolchain, есть в STM32CubeCLT)
  или `gdb-multiarch`; для RISC-V (К1921ВГ015) — `riscv-none-elf-gdb`. Скрипт ищет сам,
  иначе `--gdb путь` или переменная `LOBZIK_GDB`.
- Для обновления прошивки Лобзика ещё `pip install pyusb libusb-package` и
  STM32CubeProgrammer (`STM32_Programmer_CLI`) или `dfu-util`.

## Устройство

Один USB даёт два COM-порта: **GDB** (интерфейс 0) и **UART цели** (интерфейс 2).
Windows: `COMn`, Linux: `/dev/ttyACM*`, macOS: `/dev/cu.usbmodem*`. Скрипт различает их сам
(`lobzik.py list`). Порт GDB одновременно может держать только одна программа — закрой
отладку в VS Code (Cortex-Debug) или другой GDB, иначе порт «занят».

Разъём J1 — 14 контактов, раскладка STDC14 (как у STLINK-V3):

| Контакт | Сигнал | | Контакт | Сигнал |
|---|---|---|---|---|
| 1 | 5 В (опция) | | 2 | — |
| 3 | VTref — питание цели, по нему зонд подстраивает уровни | | 4 | SWDIO / TMS |
| 5 | GND | | 6 | SWCLK / TCK |
| 7 | GND | | 8 | SWO / TDO |
| 9 | — (ключ) | | 10 | TDI |
| 11 | GND | | 12 | nRST |
| 13 | RX цели (выход зонда) | | 14 | TX цели (вход зонда) |

VTref (3) обязателен: без него зонд не знает уровень цели и не видит её. Уровни 1.65–5.5 В.

## Частые задачи

Скрипт лежит в папке навыка: `python <папка навыка>/scripts/lobzik.py <команда>`.

```bash
lobzik.py list                          # зонды и порты
lobzik.py info                          # версия Лобзика, напряжение цели, найденные ядра
lobzik.py flash build/app.elf           # записать, сверить, сбросить (~23 КБ/с)
lobzik.py flash build/app.elf --log 20 --until "ready"   # то же + лог с самого сброса
lobzik.py reset                         # сброс SYSRESETREQ (Cortex-M)
lobzik.py uart --reset --time 15        # лог цели с самой загрузки
lobzik.py uart --send "help" --idle 2   # отправить строку, дождаться ответа
lobzik.py read 0x40020000 4             # 4 слова памяти/регистров
lobzik.py write 0x40020014 0x1          # записать слово
lobzik.py eval SystemCoreClock --elf build/app.elf   # переменная по имени
lobzik.py regs --elf build/app.elf      # где стоит ядро, backtrace, разбор отказа
lobzik.py power on                      # 3.3 В на цель от зонда
lobzik.py gdb "mon help"                # любые команды GDB; --attach — с подключением к ядру
```

Общие ключи (перед командой): `--jtag` — JTAG вместо SWD (RISC-V, К1921ВГ015);
`--freq 500k` — частота ниже 2 МГц для длинных проводов (зонд берёт ближайшую
доступную: 2M даёт 2.5 МГц); `--halt-timeout 5000`;
`--tpwr` — включить питание цели перед сканом; `--serial` — если Лобзиков несколько;
`-v` — показать полный вывод GDB.

### Прошивка

`flash` принимает ELF (пишет все секции, сверяет `compare-sections`), HEX или BIN
(`--address`, по умолчанию 0x08000000). После записи — сброс: `--reset sys` (по умолчанию,
SYSRESETREQ для Cortex-M), `hw` (импульс nRST, нужен подключённый контакт 12),
`none`, или своя команда `--reset "mon swreset"` (К1921ВГ015).
Прошивка на 800 КБ занимает около минуты. Скрипт сам ждёт GDB до 10 минут, но таймаут
инструмента, которым ты запускаешь команду, тоже поставь с запасом — не 2 минуты.
Нужно убедиться, что новая прошивка стартовала, — сразу `--log N`: скрипт пишет без
сброса, открывает UART и только потом сбрасывает плату, так лог виден с первой строки.

### Лог и проверка «запустилось ли»

Открой UART **до** сброса, иначе начало лога потеряется: `uart --reset` так и делает.
Перед сбросом скрипт выбрасывает всё, что накопилось в порту, — в выводе только свежие
строки. Скорость по умолчанию 115200 (`--baud`). Выход — по первому из условий:
`--time N` (не дольше N с), `--until "строка"` (плата напечатала нужное, например
«ready» или адрес DHCP; если не встретилось — код возврата 1), `--idle 3` (3 с тишины
после первых данных).
Цветовые коды вырезаются (`--raw` — оставить). Пусто — проверь скорость, контакты 13/14
(они названы со стороны цели: на 13 вешается RX цели), что прошивка вообще пишет в этот
UART, и что UART-порт не открыт в терминале.

### Регистры периферии на живой плате

`read` подключается к ядру, читает и отпускает его: программа на плате встаёт на
доли секунды и продолжает работу — скрипт подтверждает это строкой «ядро отпущено».
Так удобно проверять, что реально записалось в регистры (тактирование, режим GPIO,
делитель интерфейса), не добавляя отладочный вывод.

Адрес и поля бери из проекта, а не по памяти: в CMSIS-заголовке устройства
(`Drivers/CMSIS/Device/.../stm32xxxx.h`) есть `XXX_BASE`, порядок полей в структуре
`XXX_TypeDef` даёт смещение регистра (по 4 байта), а `*_Pos`/`*_Msk` — биты полей.
Если есть SVD-файл — там то же в готовом виде. Формулы (частота от делителя и т. п.) —
в Reference Manual. Читай сразу несколько соседних регистров (`read ADDR 4`) — дешевле,
чем по одному. Макросов вроде `SDMMC2` в отладочной информации обычно нет, но регистры
доступны по имени через переменные драйвера: `eval "hsd2.Instance->CLKCR" --hex --elf app.elf`
(дескрипторы HAL хранят указатель на периферию).

В Git Bash на Windows аргумент, начинающийся с `/`, превращается в путь Windows: пиши
`--hex`, а не `/x ...`.

## Плата зависла или упала

1. `lobzik.py regs --elf build/app.elf` (или `--map build/app.map`, если ELF без символов).
   Ядро останавливается, печатаются регистры, backtrace, SCB и разбор:
   - `IPSR=3` (HardFault) и биты CFSR/HFSR — причина отказа; при `BFARVALID`/`MMARVALID`
     виден адрес, к которому обращались;
   - LR вида `0xFFFFFFFx` — ядро в обработчике; добавь `--stack 8`, чтобы увидеть кадр
     прерванного кода (R0–R3, R12, LR, **PC**, xPSR) — PC в кадре и есть место падения;
   - `CFSR/HFSR = 0` — отказа нет, ядро крутится в цикле или ждёт: смотри PC/LR и backtrace.
2. Повтори `regs` 2–3 раза: если PC каждый раз в одной функции — это и есть место
   зависания; если в idle-задаче RTOS — система жива, ждёт событий.
3. `--keep-halted` оставляет ядро стоять, чтобы прочитать ещё что-то (`read`, `eval`).
   Дальше — `reset`.

Не ставь `set $pc` и не прыгай по адресам на рабочей плате ради эксперимента: ядро может
уйти в состояние, где `attach` не проходит, и поможет только кнопка сброса или питание.

## Цель не находится

Порядок проверки — по выводу `lobzik.py info`:

| Видно | Причина | Что делать |
|---|---|---|
| `Target voltage: 0.0V` | нет питания цели или VTref | подать питание; от зонда — `power on` |
| напряжение есть, `No usable targets` | шлейф, режим, частота | проверить SWDIO/SWCLK/GND, `--freq 500k`, для JTAG-целей `--jtag` |
| ядро в списке, `Attaching ... failed` | ядро не остановилось за 2 с | `--halt-timeout 5000`; не помогло — сброс кнопкой/nRST/питанием |
| GDB висит, таймаут | Лобзик подвис | переподключить USB Лобзика |
| порт «занят»/`Access denied` | порт держит VS Code, другой GDB, терминал | закрыть программу |

Подробнее по симптомам — `references/troubleshooting.md`.

## Питание цели от Лобзика

`power on` (`mon tpwr enable`) подаёт 3.3 В на контакт 3 с мягким стартом: ток растёт
постепенно, чтобы конденсаторы цели не просадили сам зонд. Если цель уже запитана
своим источником (> 0.5 В), зонд питание не включает — это защита, а не ошибка.
Цель питается от того же стабилизатора 3.3 В, что и сам зонд (всего ~400 мА от USB):
отладочной плате хватает, а плату с моторами, радиомодулем на передаче, светодиодными
лентами питай от своего источника. `power off` — выключить.

## Обновление прошивки Лобзика

```bash
lobzik.py reflash                       # свежая прошивка из релизов KitsLab
lobzik.py reflash fretsaw_bmp.bin       # или свой файл
```

Без аргумента скрипт скачивает `fretsaw_bmp.bin` из последнего релиза
(https://github.com/Kits-Lab-Dev/blackmagic/releases/latest), затем переводит Лобзик
в загрузчик ST командой по USB (DFU_DETACH; работает с прошивкой
от 30.09.2026, версии `v2.1.0-…` и новее), пишет `.bin` с 0x08000000, сверяет и ждёт зонд.
Со старой прошивкой или если команда не прошла — вручную: зажать кнопку на Лобзике,
подключить USB, отпустить; Лобзик появится как «STM32 BOOTLOADER», дальше та же команда.
Перед перешивкой отключи остальные Лобзики: команду в загрузчик получают все.
Версию после перешивки показывает `info`.

## Особые цели

- **К1921ВГ015** (RISC-V, плата «Вагонка»): только JTAG, свои команды сброса и стирания —
  `references/k1921vg015.md`.
- Остальные цели Black Magic Debug (STM32, GD32, nRF5x, RP2040, SAM, LPC и другие —
  полный список в документации Black Magic Debug) работают теми же командами.
  После `attach` у части целей появляются свои команды: `lobzik.py gdb --attach "mon help"`.
